把一部金锁玉关的讲义、笔记、作业与批改，整理成可查、可导、可迁移的学习库。

- 在线站点：<https://liumingmusic.github.io/jinsuo-yuguan/>
- 全站只认一份 Markdown 源，网页、思维导图、导出文件都由它生成，不从渲染结果反推

## 经文

`经文/*.md` 是全站经文的**唯一源**，一山一篇（另有三篇卦体），篇内固定两栏：

- **我的经文**——我的手笔。目前全部待补。
- **老师经文**——老师提供的版本。目前也全部待补。

**没有的不代写**：两栏一律留占位〔待补〕。

底本是文献，不算谁的经文，各山正文里逐句列出。

由 `build.py` 投影到四处：Ⅱ 卦山线各山章节内、Ⅲ 作业线《经文总表》、Ⅳ 导图线脑图页下、Ⅴ 经文线专页。**四处内容一字不差**，改一处四处一起变。

其中 Ⅴ 经文线是专页：Ⅱ Ⅲ Ⅳ 三处是行文里的一段，栏上下接着走；Ⅴ 线一卦一页，两栏左右并排，专门用来对读与填稿。

禁抄校验用 `/tmp/jw/check2.py`（阈值 5 字）与 `check4.py`（阈值 4 字）：把老师原版 docx 与站内底本收敛成禁抄诗句清单，再扫经文是否撞句。当前双阈值均 0 命中。

## 版式

外壳 `--shell:1800px`，正文**一档走满列**：

所有正文元素——段落、清单、引文、图框、表格、代码块、卡片、脑图、状态条、上下页、h2 分隔线——
一律吃满中间那一列（1920 屏下正文页 1117px），左右边界与表格完全对齐。

> 2026-11-08 取消原「文字档 800px / 宽内容档吃满」的两档做法。
> 两档只是同左边界，右边差 317px，看上去像表格从正文里顶出来（用户反馈「只有表格变宽了，其余内容宽度没变」）。

响应式断点：1560（藏右目录转两栏）→ 1240 → 1024 → 900（单栏）→ 640 → 560。

## 目录

```
内容/        唯一内容源（Markdown）
  Ⅰ-课程线/  Ⅱ-卦山线/  Ⅲ-作业线/  附录/
脑图/        Markdown 大纲 → xmind/mm/opml
经文/        经文的唯一源（一山一篇，篇内两栏）
_工具/       build.py（站点）、md2mind.py（导图）、deploy_gh.py（发布）
_数据/       作业状态.json（作业与批阅状态的唯一数据源）
导出/        xmind / mm / opml
站点/        构建产物，不纳入版本库，由 gh-pages 分支发布
```

## 本地跑

```bash
python3 _工具/build.py        # 生成 站点/
python3 _工具/md2mind.py 脑图/ 导出/ --all
cd 站点 && python3 -m http.server 8000
```

只用标准库，无第三方依赖。

## 发布

`main` 存源码，`gh-pages` 存构建产物根目录，GitHub Pages 服务后者。改了内容重建后：

```bash
python3 _工具/deploy_gh.py --site
```

脚本走 REST objects API 而非 `git push`，因为本机 `git push` 会挂死。

## 几条口径

整理时守的规矩，写在这里免得以后走样：

- 火尖砂就叫火尖砂，不叫破军砂（破军是九星名）
- 真水最强，证据是蒸发
- 冰箱判砂，马路算砂
- 三合是同一件事的三个阶段，不是一个五行
- 金锁只有大太极与小太极，没有第三层
