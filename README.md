# 金锁玉关 · 二十四山研习库

把一部金锁玉关的讲义、笔记、作业与批改，整理成可查、可导、可迁移的学习库。

- 在线站点：<https://liumingmusic.github.io/jinsuo-yuguan/>
- 全站只认一份 Markdown 源，网页、思维导图、导出文件都由它生成，不从渲染结果反推

## 里面有什么

| 部分 | 内容 |
|---|---|
| Ⅰ 课程线 | 12 讲，每讲理法、技法、案例、答疑，含 73 处配图占位待补 |
| Ⅱ 卦山线 | 坎（壬子癸）、坤（未坤申）、震（甲卯乙）九山，逐山：山性类象 / 见水 / 见砂 / 形煞叠加 / 技法布局 / 我的经文与老师口播 / 差异存疑 |
| Ⅲ 作业线 | 11 次作业，题面、批语、拆解；页顶显作业状态与批阅状态；另有《经文总表》一页 |
| Ⅳ 导图线 | 坎、坤、震各一张骨架图，编号 Ⅳ-01～Ⅳ-03，图下附本卦经文 |
| 附录 | 经文对照总表、技法总章、术语表、存疑清单、二十四山速查 |

二十四山为全图，当前精讲坎、坤、震三卦九山，其余 15 山标注为「本阶段未及」，不编具体断语。

## 经文

`经文/*.md` 是全站经文的**唯一源**，一山一篇（另有三篇卦体），篇内固定两栏：

- **我的经文**——我的手笔。目前只有坎卦壬、子、癸三山，是第 5 课作业里交上去的四句原稿。
- **老师口播 · 据课堂记录整理**——课堂上的讲师原话。目前收了坤卦的卦体、未山、坤山。

**没有的不代写**：老师还没讲到的山、我也还没写的山，两栏一律留占位〔待补〕。

底本与口播本是文献，不算谁的经文，在附录的《经文对照总表》里。

由 `build.py` 投影到三处：Ⅱ 卦山线各山章节内、Ⅲ 作业线《经文总表》、Ⅳ 导图线脑图页下。**三处内容一字不差**，改一处三处一起变。

禁抄校验用 `/tmp/jw/check2.py`（阈值 5 字）与 `check4.py`（阈值 4 字）：把老师原版 docx 与站内底本/自译/试作收敛成禁抄诗句清单，再扫经文是否撞句。当前双阈值均 0 命中。

## 版式

外壳 `--shell:1800px`，正文分两档走：

| 档 | 宽度 | 谁走这一档 |
|---|---|---|
| 文字档 | `--measure:50rem`（800px，约 50 字/行） | 段落、清单、引文、图框 |
| 宽内容档 | 吃满整列（正文页 1117px） | 表格、代码块、卡片、脑图、状态条、上下页、h2 分隔线 |

两档从同一条左边界起，右侧才齐。h2 分隔线归宽内容档——它是章节边界，与下面的表格同界，宽窄两档就被这条线分开，不会看着像表格顶破了章节。

响应式断点：1560（藏右目录转两栏）→ 1240 → 1024 → 900（单栏）→ 640 → 560。

## 目录

```
内容/        唯一内容源（Markdown）
  Ⅰ-课程线/  Ⅱ-卦山线/  Ⅲ-作业线/  附录/
脑图/        Markdown 大纲 → xmind/mm/opml
经文/        经文的唯一源（一山一篇，篇内两栏）
_工具/       build.py（站点）、md2mind.py（导图）、deploy_gh.py（发布）
_数据/       作业状态.json（作业与批阅状态的唯一数据源）
导出/        xmind / mm / opml
站点/        构建产物，不纳入版本库，由 gh-pages 分支发布
```

## 本地跑

```bash
python3 _工具/build.py        # 生成 站点/
python3 _工具/md2mind.py 脑图/ 导出/ --all
cd 站点 && python3 -m http.server 8000
```

只用标准库，无第三方依赖。

## 发布

`main` 存源码，`gh-pages` 存构建产物根目录，GitHub Pages 服务后者。改了内容重建后：

```bash
python3 _工具/deploy_gh.py --site
```

脚本走 REST objects API 而非 `git push`，因为本机 `git push` 会挂死。

## 几条口径

整理时守的规矩，写在这里免得以后走样：

- 火尖砂就叫火尖砂，不叫破军砂（破军是九星名）
- 真水最强，证据是蒸发
- 冰箱判砂，马路算砂
- 三合是同一件事的三个阶段，不是一个五行
- 金锁只有大太极与小太极，没有第三层
- 讲义底本之间、底本与口播之间的冲突不悄悄选一个，逐条记在各页「差异与存疑」里
